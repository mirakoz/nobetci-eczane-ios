## 2026-06-15 - Stable Identities and Static Resource Centralization
**Learning:** Using a computed `id` that returns a new `UUID()` on every access is a critical performance anti-pattern in SwiftUI. It causes the framework to lose track of view identity, leading to the destruction and recreation of every list element during any state update, which kills scroll performance and breaks animations. Additionally, performing O(N log N) sorting of static data (like a city list) during view initialization adds unnecessary latency to UI transitions.
**Action:** Always use stable identifiers (like slugs or unique database IDs) for `Identifiable` models. Centralize static datasets as pre-sorted `static let` properties to move computation from the Main Actor's render loop to app load time.
