## 2026-06-15 - SwiftUI Identity and String Optimization
**Learning:** Using a computed `UUID()` as an `id` for models in SwiftUI Lists (like `District`) is a major performance anti-pattern. It forces SwiftUI to recreate every row view on every state change because it thinks every item has a new identity. Additionally, sequential `replacingOccurrences` calls on strings create multiple temporary allocations; a single-pass loop with `reserveCapacity` is significantly more efficient.
**Action:** Always verify that `Identifiable` models used in `List` or `ForEach` have stable IDs (e.g., from the API data). Prefer single-pass character loops for complex string transformations. Move immutable data processing (like sorting city lists) to `static let` constants to avoid redundant work during View re-initialization.
